# INCIDENT INVESTIGATION REPORT: RCA-2025-00012
**Service:** User Profile Service  
**Completion Date:** 2025-06-05T16:00:00Z  
**Linked Incidents:** INC-2025-00615  
**Investigation Owner:** Customer Identity  
**Root Cause Category:** Software Defect  
**Business Impact:** EUR 9,800 (estimated)  

## Summary
After a profile contract update, the API gateway decoded some profile fields with the wrong type and customers saw empty or wrong values.

## Timeline
- 07:50 UTC: Profile contract v2.7 deployed.
- 08:02 UTC: First transcoder errors.
- 08:15 UTC: Customer Experience reports wrong profile data.
- 09:00 UTC: Contract update rolled back.

## Root Cause
Contract v2.7 reused protobuf field number 5 of a removed field for a new field of a different type. The gateway still used the old descriptor and decoded the new field wrongly.

## Five Whys
1. Why were fields wrong? The gateway decoded field 5 with the old type.
2. Why? Field number 5 was reused for a new field with a different type.
3. Why was it reused? The removed field was not marked as reserved.
4. Why was that not caught? No breaking-change check on the contract.

## Contributing Factors
- **Change / Release:** Contract v2.7.
- **Process:** No breaking-change check.
- **Dependencies:** Gateway transcoder uses its own copy of the descriptor.

## Corrective Actions
Rolled back and marked removed fields as reserved.

## Preventive Actions
Added a breaking-change check (buf breaking) to the gateway repository.
