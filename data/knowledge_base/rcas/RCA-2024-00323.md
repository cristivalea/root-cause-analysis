# INCIDENT INVESTIGATION REPORT: RCA-2024-00323
**Service:** Auth Service  
**Completion Date:** 2024-10-22T20:00:00Z  
**Linked Incidents:** INC-2024-01207  
**Investigation Owner:** IAM Engineering  
**Root Cause Category:** Configuration Error  
**Business Impact:** EUR 6,500 (estimated)  

## Summary
After a signing key rotation, several services kept an old key list and rejected new tokens.

## Timeline
- 16:52 UTC: Incident raised.
- 16:54 UTC: Assigned to IAM Engineering.
- 17:28 UTC: Reassigned to Network Engineering.
- 17:52 UTC: Workaround applied.
- 18:23 UTC: Service restored.

## Root Cause
The key list cache in downstream services refreshed every 60 minutes, while the old key was removed 10 minutes after rotation. Tokens signed with the new key were rejected until the caches refreshed.

## Five Whys
1. Why did services return 401? They rejected tokens signed with the new key.
2. Why? Their cached key list did not contain the new key yet.
3. Why was the cache outdated? The cache refreshed only every 60 minutes.
4. Why did that matter? The rotation removed the old key after only 10 minutes.

## Contributing Factors
- **Change / Release:** Key rotation procedure.
- **Configuration:** Cache refresh interval longer than the key overlap period.
- **Process:** Rotation runbook did not mention downstream caches.

## Corrective Actions
Kept both keys published for 24 hours after each rotation.

## Preventive Actions
Downstream services now refresh the key list when they meet an unknown key id.
