# INCIDENT INVESTIGATION REPORT: RCA-2026-00052
**Service:** Payment API  
**Completion Date:** 2026-02-17T13:00:00Z  
**Linked Incidents:** INC-2026-00065, INC-2026-00100  
**Investigation Owner:** Payments Platform Engineering  
**Root Cause Category:** Configuration Error  
**Business Impact:** EUR 17,500 (estimated)  

## Summary
Enabling a feature flag for all merchants sent requests to a code path that needs configuration most merchants did not have.

## Timeline
- 09:50 UTC: Incident raised.
- 10:00 UTC: Assigned to Payments Platform Engineering.
- 11:37 UTC: Workaround applied.
- 12:03 UTC: Service restored.

## Root Cause
The instalments_v2 flag was switched on globally. Merchants without instalment settings hit a null value in the plan resolver and the request failed with HTTP 500.

## Five Whys
1. Why did checkouts fail? The Payment API threw a NullPointerException for some merchants.
2. Why the exception? The instalment resolver read settings that did not exist for those merchants.
3. Why were they on that code path? The feature flag was enabled for all merchants at once.
4. Why at once? The flag rollout had no staged percentage plan.

## Contributing Factors
- **Change / Release:** Global feature flag rollout.
- **Configuration:** Missing default for merchants without instalment settings.
- **Process:** Feature flag changes were raised as standard changes without review.

## Corrective Actions
Disabled the flag and added a default for merchants without instalment settings.

## Preventive Actions
Feature flag rollouts above 10% of merchants now require a normal change with a staged plan.
