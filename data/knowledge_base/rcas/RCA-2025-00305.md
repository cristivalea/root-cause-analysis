# INCIDENT INVESTIGATION REPORT: RCA-2025-00305
**Service:** Auth Service  
**Completion Date:** 2025-10-02T12:30:00Z  
**Linked Incidents:** INC-2025-01305  
**Investigation Owner:** Identity Platform Engineering  

## Summary
Auth service pods repeatedly restarted after exceeding their memory limits, resulting in failed login attempts and elevated authentication latency during a routine deployment.

## Timeline
- 08:05 UTC: Deployment manifest updated resource requests for auth worker pods.
- 08:12 UTC: New pods entered a restart loop after OOM kills.
- 08:27 UTC: Incident commander rolled back the Kubernetes memory configuration.
- 08:40 UTC: Service recovered and login success rates returned to baseline.

## Root Cause
The deployment manifest set a Kubernetes memory limit of 256Mi for auth service pods, far below the actual runtime requirement of 1Gi, causing the runtime to be OOM-killed repeatedly under normal login load.

## Contributing Factors
The deployment pipeline did not validate memory sizing against the application baseline and the change was promoted without a load test.

## Corrective Actions
Adjusted memory limits to the validated production profile, enforced deployment policy checks for resource sizing, and added an automated capacity gate before rollout.
