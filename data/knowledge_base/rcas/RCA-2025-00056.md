# INCIDENT INVESTIGATION REPORT: RCA-2025-00056
**Service:** Reporting Service  
**Completion Date:** 2025-02-21T21:00:00Z  
**Linked Incidents:** INC-2024-01272, INC-2025-00153  
**Investigation Owner:** Data Platform  
**Root Cause Category:** Software Defect  
**Business Impact:** EUR 3,000 (estimated)  

## Summary
A cache clearing bug made every dashboard recompute at the same time and overloaded the warehouse.

## Timeline
- 16:03 UTC: Incident raised.
- 16:13 UTC: Assigned to Data Platform.
- 17:03 UTC: Workaround applied.
- 17:19 UTC: Service restored.

## Root Cause
A release changed the cache key prefix, so all cached dashboards were invalid at once. Hundreds of users triggered the same heavy queries in parallel.

## Five Whys
1. Why were dashboards slow? The warehouse CPU was at 100%.
2. Why? Hundreds of identical heavy queries ran in parallel.
3. Why in parallel? All caches became invalid at the same moment.
4. Why at once? A release changed the cache key prefix.

## Contributing Factors
- **Change / Release:** Cache key prefix changed in a release.
- **Capacity:** Warehouse sized for cached traffic only.
- **Configuration:** No request coalescing.

## Corrective Actions
Enabled request coalescing so one query serves all waiting users.

## Preventive Actions
Cache key changes now warm the new cache before switching.
