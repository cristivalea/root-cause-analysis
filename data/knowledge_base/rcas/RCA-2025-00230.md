# INCIDENT INVESTIGATION REPORT: RCA-2025-00230
**Service:** Billing Service  
**Completion Date:** 2025-06-20T15:00:00Z  
**Linked Incidents:** INC-2025-00512, INC-2025-00548  
**Investigation Owner:** Finance Engineering  
**Root Cause Category:** Configuration Error  
**Business Impact:** EUR 27,500 (estimated)  

## Summary
The month-end invoice aggregation ran for hours and timed out two months in a row, delaying the finance reports.

## Timeline
- 22:00 UTC: Month-end aggregation started.
- 22:10 UTC: First statement timeouts.
- 22:40 UTC: Finance Operations raised the incident.
- 01:05 UTC: Aggregation completed region by region.

## Root Cause
An ORM migration dropped the composite index (account_id, billing_period) on invoice_lines. The month-end aggregation filters by billing period, so every run scanned the whole table.

## Five Whys
1. Why did the reports time out? The aggregation queries exceeded the statement timeout.
2. Why were they slow? They scanned the whole invoice_lines table.
3. Why a full scan? The composite index on (account_id, billing_period) was missing.
4. Why was it missing? An ORM migration recreated the table without it.
5. Why was that not noticed? Only the month-end run uses that filter, so it showed up once a month.

## Contributing Factors
- **Change / Release:** ORM migration recreated the table.
- **Capacity:** 1.2 billion rows scanned at month end.
- **Process:** No check of the query plans after migrations.

## Corrective Actions
Created the composite index again (CHG-2025-00409).

## Preventive Actions
Compare the index list before and after every table migration.
