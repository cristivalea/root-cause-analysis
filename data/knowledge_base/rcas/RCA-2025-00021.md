# INCIDENT INVESTIGATION REPORT: RCA-2025-00021
**Service:** Customer Portal  
**Completion Date:** 2025-01-20T20:00:00Z  
**Linked Incidents:** INC-2025-00004  
**Investigation Owner:** Digital Commerce Engineering  
**Root Cause Category:** Configuration Error  
**Business Impact:** EUR 14,500 (estimated)  

## Summary
A CDN rule cached a personalised page fragment and served it to other customers.

## Timeline
- 18:05 UTC: Incident raised.
- 18:08 UTC: Assigned to Digital Commerce Engineering.
- 19:02 UTC: Workaround applied.
- 19:13 UTC: Service restored.

## Root Cause
The new caching rule stored the account header fragment without the session cookie in the cache key, so the first customer's greeting was served to others.

## Five Whys
1. Why did customers see another name? The CDN served a cached header fragment.
2. Why was it cached? A new rule cached account page fragments at the edge.
3. Why was it shared? The cache key did not include the session.
4. Why was it not caught? The rule was tested with a single test account.

## Contributing Factors
- **Change / Release:** New CDN caching rule.
- **Configuration:** Cache key without the session.
- **Process:** CDN rules raised as standard changes without a privacy review.

## Corrective Actions
Removed the rule and purged the cache.

## Preventive Actions
CDN rules on personalised paths now need a normal change and a test with two accounts.
